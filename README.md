## 简介

QuillPlus 是一个面向 AstrBot 的沉浸式角色扮演（RP）增强插件。它通过世界书、写作素材库、角色卡、文档 RAG、动态记忆和状态栏六个模块的联动，为 LLM 驱动的角色提供结构化记忆、上下文注入和状态追踪能力。

支持通过聊天指令（手机端可用）和 Web 管理面板两种方式进行交互。

## 特性

### 角色卡系统 (Character Card V2)

实现 Character Card V2 标准核心字段，兼容多种导入来源。

- 支持 PNG / JPG / WebP / JSON 格式的 V2/V3 卡片导入（内嵌世界书 character_book 自动转换并绑定，可在「配置 → 世界书 → 角色卡导入自动转换内嵌世界书」关闭），导出为 PNG（含头像）或 JSON
- **身份键与显示名解耦**：新建/导入的角色卡一律用 12 位短 ID 作内部标识，改名只是改名——对话记忆、会话绑定与聊天记录在改名前后连续（已有旧卡零迁移照常使用；导出的 V2 卡携带身份信息，导入往返不换卡）
- 内置正则解析引擎，支持 W++、Raw Text 等纯文本格式导入
- 头像不随列表内联返回，按需懒加载（Data URL / 静态端点），避免 WebUI iframe 沙箱的跨域限制
- 支持从 Character.AI / Chub 等平台导入卡片
- **头像自定义裁剪**：Web 面板内置裁剪器，支持拖拽移动 + 滚轮缩放，Canvas 生成 300×300 方形 PNG
- **由 AstrBot 人格导入**：角色卡页工具条新增「由人格导入」，直接读取 AstrBot 面板
  「人格」页里已创建的人格（列出设定字数与开场对话条数，与现有角色卡同名时标注提示），
  用你自己配置的摘要模型（「配置 → RAG 与动态记忆 → LLM 提供商」）整理成角色卡的
  `name` / `summary` 与四段核心设定（`personality` / `scenario` / `examples_of_dialogue`
  / `first_message`）；重名会自动加「（导入）」后缀，也可以在弹窗里手动指定名称
  （手动指定的名称撞重名会在调用模型之前就报错）。**人格本体只读**：不修改、不删除
  AstrBot 里的人格，只读出来转成角色卡

### 世界书系统 (Worldbook)

关键词触发的设定条目管理，prompt 按需注入。

- 常驻条目全局注入，构建稳定基调设定
- 关键词模糊匹配 + 灵敏度调节，命中时注入对应条目
- **条件解锁条目**：条目可附条件（如 `好感度 >= 70`、`剧情阶段 in 约会,婚礼`），会话变量达标才注入，常驻条目同样支持；条件不成立、变量未采集或写法不支持时一律不注入，原因可在注入诊断的近失明细里看到。条目表单可直接填写/清除，ST 格式导入导出往返不丢
- 支持注入到用户消息之前（前置模式）
- 每个角色可绑定专属世界书集合，角色切换时自动挂载/卸载

### 写作素材库 (Writing Resource)

内置 65 条预置写作指引，覆盖叙事、描写、节奏、对白、场景、情绪等通用虚构写作维度，开箱即用。素材库完全可编辑：可在面板增删改、按分类绑定角色卡、或从自己的素材库导入。

- SQLite + FTS5 全文检索，关键词毫秒级命中
- 四层 Prompt 装配（协议层 → 素材层 → 触发层 → 安全层），自动截断
- 不同角色可绑定不同分类，避免设定串扰

### 文档知识库 (Doc RAG)

上传外部文档，AI 检索后注入 prompt。

- 支持 .txt / .md 等纯文本格式（PDF / Office 等二进制格式不支持）
- 段落优先分块 + 固定长度兜底，overlap 保持上下文连贯
- 支持 API Embedding（如 SiliconFlow）和本地模型 fallback
- 独立 Rerank Provider 提升检索精度
- **兼容 AstrBot 内置知识库**：AstrBot 面板「知识库」页创建的库会自动出现在
  `/doc list` 与角色卡编辑器的绑定列表中（`kb:库名` 标识，标注 `[内置库]`），
  绑定、检索、注入与本地文档完全同权。内置库使用 AstrBot 自身的 Embedding
  配置，无需在本插件重复配置；`auto`（全库）模式会一并检索全部非空内置库，
  隔离（custom）模式只检索勾选项。内置库的新建/删除/文档管理仍在 AstrBot
  面板进行，本插件只做绑定与检索（插件配置页与羽笔面板「RAG 与动态记忆」节
  均有总开关 `rag.astrbot_kb_enabled`，默认开启；关闭后行为与旧版一致，
  面板保存即时生效、无需重载插件）
- **子知识库分组（插件内自建 + 勾到单篇文档）**：面板「文档知识库」页分两个平级大组
  ——「插件文档库」与「AstrBot 兼容」。插件文档库支持**新建分组**（子知识库），上传时
  选目标分组、之后用一个下拉随时改组，分组可改名/删除（组内文档回到「未分组」，
  没进任何分组的文档依然存在）。分组只是元数据（`rag_doc_groups.json`），所有插件
  文档共用同一份向量索引，改名/改组不需要重新上传。角色卡「高级扩展 → 文档知识库」
  是三级勾选：勾大组＝全选，勾分组＝整个分组的文档（`grp:组名`），勾库＝整库
  （`kb:库名`），展开后还能只勾其中几篇（插件文档＝文件名，内置库＝`kb:库名/文档名`）。
  只挂单篇时检索会把候选池放大后再按文档名过滤，不会被同库其它文档挤掉

### 动态记忆 (Vector Memory)

自动摘要对话内容，向量化存储后跨会话检索注入。

- 默认按会话与角色隔离记忆，切卡不串写；开发中的会话组可显式选择共享入口
- 调用 LLM 将对话精炼为短文本并生成向量
- SQLite BLOB 存储向量 + NumPy 余弦相似度检索
- **核心记忆锚定**：可将关键记忆钉住（`is_core=1`），不参与 Top-K 竞争，无条件注入 `<core_memory>` XML 标签，类似人设基石
- **核心记忆自然语言注入**：在对话中通过 `@记住：...` 指令直接写入核心记忆，无需进入面板操作
- **全自动闲时反思**：系统空闲时自动分析未提纯的记忆，总结核心特质与关键事实，迭代角色深层设定
- **混合检索**：FTS5 (BM25) + Vector 混合检索，RRF 融合 + Ebbinghaus 时间衰减过滤
- **LRU 会话缓存**：加速同会话反复检索，减少磁盘与序列化开销
- 聊天指令管理：`/memory list/del/clear/learn/search/pin`

### 状态栏系统 (Status Bar)

追踪角色与用户的交互状态，将 LLM 输出结构化为可读面板。

- 6 级降级解析（code block / LOVE_DATA / STATUS / raw / lenient / LLM 提取）确保格式兼容，逐级命中率可在 /quill debug 查看
- 工具调用与响应两路钩子协作，避免重复注入
- 关闭状态栏后自动剥离残留格式（关闭时也会清除历史上下文里已渲染的状态栏，避免边禁边示范）
- 字段名可自定义，支持分支剧情选项生成；改字段名会同步影响提示词契约、剥离器与解析器
- **格式契约单一来源**：字段行/示例/选项块统一由 `build_status_contract()` 生成，改一处全链路跟随
- **平台双模板**：QQ/微信等不渲染 Markdown 的平台自动改用分隔线模板，避免 `**状态栏**` 与围栏原样显示
- **会话级开关**：`/quill statusbar on|off|auto` 可对单个会话临时覆盖面板开关（不写回配置）
- **LLM 智能提取**：前 5 级全部失败时调用轻量 LLM 做结构化提取（3s 超时保护，默认关闭）
- **模型路由**：状态栏提取 LLM 可独立配置（`status_bar.llm_provider_id`），留空回退到 RAG 摘要 LLM，建议配置轻量模型降低成本

### 安全与并发

- 群聊权限控制：admin_users 白名单作用于聊天平台全部**写类**指令（改持久状态的子命令），读类指令保持开放；Web 面板由 AstrBot 鉴权保护
- 全量 HTML 转义 + 模式值白名单，防止 XSS 注入
- 世界书导入名称校验，仅允许字母数字 / 下划线 / 短横线 / CJK
- 状态文件采用 tmp + fsync + os.replace 原子写入，防崩溃损坏
- FAISS 索引基于 SQLite rowid，L2 归一化确保检索一致性
- 后台工作统一管理；长任务可在面板查看进度、拒重与安全点取消

### 注入诊断 (Trace)

排查「设定漏注入 / 角色失忆」类问题：每轮对话记录命中了什么、以什么顺序注入、哪个环节降级，面板「注入诊断」页与 `/quill debug` 同源（同一 trace_id 结论一致）。

- 面板按会话查看最近轮次，点开单轮可见各模块命中明细（哪本世界书、哪篇文档）、注入段序、粗估 Token、耗时与降级原因
- **三阶漏斗**：候选了几条 → 最终注入几条 → 被挤掉的是哪条、为什么（关键词不够门槛 / 条件未达成 / 超过注入上限 / 分类去重），「差一点命中」不再静默丢弃
- **裁剪事件**：预算超限时自动先撤触发日志、再裁 RAG 尾部（核心记忆永不入裁剪范围），每轮记录丢了哪段、裁了多少字；注入构成按「实际注入量」口径显示
- **脱敏预览**：点开单轮可按段查看实际注入的文本（RAG 检索段只给长度不展示原文；每会话仅保留最新一轮的预览）
- **模拟检索**：面板输入一句话预演这轮会注入什么（可选角色卡、可带会话变量），只读沙盒零写入、默认零模型调用；`/quill test wr|wb|mem|kb` 输出末尾附 Trace 锚点，面板可查同一轮模拟
- **静态体检**：一键检查世界书与角色卡的常见隐患——重复/过于宽泛/当前灵敏度下不可达的关键词、永远无法触发的死条目、条件语法错误、绑定了已不存在资源的「幽灵绑定」、常驻内容预算水位
- **实时视图**：诊断页「实时」开关开启后新一轮自动推入列表（不可用时自动降级为轮询）；剧情决策的判定路径（数字直选 / 模型判定 / 未达阈值）也记录在轮次详情里
- 未激活轮也记录（能看出「这句为什么没进 RP」）；`/quill debug` 的「Trace」行即该轮 id 锚点
- 纯内存 ring buffer（每会话默认 20 轮、全局 200 轮，超限淘汰最旧），重启即清、不写盘
- 脱敏：会话只以 SHA-256 前 16 位哈希标识；错误只记类别不记内容，不含原始对话文本
- 配置组「诊断追踪」：默认开启；关闭后零采集零记录。只读注入流程已有数据，零额外模型调用

## 管理面板

进入 AstrBot WebUI → 插件 → Pages / 插件配置。**前端面板已按 macOS 27（Liquid Glass）桌面应用形态重建**——不只是配色，而是信息架构、控件体系、材质、动效与操作方式都对齐 Apple HIG 现行规范。

- **窗口架构（边栏优先）**：侧栏是应用骨架，承载静态分组导航与七个页面的实时计数（分组标题为静态 section label，不折叠）；内容区为通栏标题带 + 列表，页面操作收进主按钮组，卡片上的低频操作走右键上下文菜单
- **控件体系**：控件高度取 macOS 实测值（`--h-control` 24px、`--h-row` 28px、`--h-control-sm` 20px），宽度令牌（`--w-num` / `--w-ctl` / `--w-wide`）与字阶（10/11/12/13/15/17/22/26）同样按 macOS 实测；圆角按控件族分别取值（按钮 6、行/菜单项 5、复选框 5.5、卡片 12、模态 16、菜单 8、弹窗 26），配置页控件按三档宽度左对齐，并排控件高度统一，消除基线错位
- **材质按表面分层**：侧栏、标题栏、菜单、浮层、通知各用各自的模糊强度（100/6/20/30/15px，深色另有取值），菜单用 macOS 的玻璃填充 + 多层描边阴影；`prefers-reduced-transparency` 下材质退化为纯色
- **macOS 桌面交互**：弹层从窗口顶部垂落（sheet 语义）、右键上下文菜单、列表方向键导航（roving tabindex）、双击直接编辑、行内操作悬停显现
- **卡片 = 浏览，编辑 = 模态**：卡片网格高度恒定（固定行高 132px、标签单行裁切），不就地展开编辑器，因此翻页时列表不会重排
- **分页按真实几何计算**：每页条数由容器宽度（列数）与可用高度（行数）反推，行高/间距直接读 CSS 计算样式（单一来源）；分页栏钉在内容区底部、按钮定宽，连续翻页鼠标不必移动，页码在 resize / 筛选 / 删除后自动夹紧到有效范围
- **配置页空间分配**：「注入引擎」为两列纵向栈（卡内不再留空洞）；「状态栏」为左列设置项 + 右列整列 Markdown 模板编辑器（模板 538px 宽、约 13 行可见）
- **下拉与分段控件**：选项多的下拉用自绘 listbox（材质浮层、选中项打勾、方向键/首字母跳转、视口边缘自动翻转）；2–3 个固定选项的枚举用分段控件（选项常显、一次点击选中）。原生 `<select>` 始终保留为值存储，功能零回归
- **语义分层**：侧栏与配置分区导航是应用导航 / 页内跳转（`aria-current`、`role="region"`），只有真正切换同一区域内容的地方（记忆子页、角色卡模态）用 tablist + tabpanel
- **界面字体**：macOS 使用系统 SF Pro + 苹方（零下载）；其他平台自动加载 HarmonyOS Sans（按 unicode-range 分块，仅下载实际用到的字块）

## 用量与缓存（试用）

管理面板新增「模型用量」。可按会话、角色 ID、供应商 ID、模型、用途和时间范围查询明细，并查看按会话组、用途、模型、角色、供应商及 UTC 日期汇总的数据。只记录会话标识、调用身份、时间、状态、模型、计数和费用等元数据，不保存提示词、模型回复或密钥。管理身份可查询和清空台账。

- 默认记录用量，保留 30 天、上限 20000 条；可在配置中关闭或调整。物理清理按批执行，常规写入最多延后 99 条；调整上限后在下次记录时清理。过期记录不参与查询。
- 主对话仅覆盖宿主最终响应，工具循环中的中间调用、未触发响应钩子的失败以及供应商内部重试可能无法逐次观测。辅助摘要、反思、状态提取、剧情决策、人格转换、向量化与重排在插件调用边界记录。向量化/重排接口未返回计数时显示未知。
- 未报告、报告为零、部分有报告分别保留。宿主默认零不冒充供应商真零；缓存命中率只对有可靠报告的样本按输入 token 加权，显示样本数与适用调用覆盖率。字符估算和提示段变化不作为真实命中率。
- 金额优先采用带明确币种的供应商报告，或按调用开始时的手动价格表推算；确认实际使用 OpenRouter 官方端点时，费用单位按其协议为 USD。缺缓存写入报告时，只给单独标注的部分推算，可能低估；原生 Anthropic 未暴露创建分项时保持金额未知。Gemini 的 token 推算不含显式缓存存储时长费用。存在未知回退且未报告实际模型时不套用请求模型价格。面板按币种和计价来源分别展示。
- 台账独立保留，不进入剧情备份，不随角色剧情读档回退。关闭记录不会删除已有记录。
- 会话与参与者标识以脱敏摘要保存；旧台账自动迁移。汇总覆盖全部筛选结果，明细单独分页。记录通过有界后台队列写入，失败、队列满或关闭时未确认的记录显示缺口，重载和清空调用台账不重置累计缺口。损坏的旧行先留安全副本，再隔离并显示数量，其余记录仍可查询。

手动价格表的单位是「每百万 token」，模型名或 `provider_id/模型名` 为键。示例仅演示格式，数值请按实际供应商价格填写：

```json
{
  "example-model": {
    "currency": "USD",
    "version": "manual-2026-10",
    "input": 1,
    "output": 2,
    "cache_read": 0.1,
    "cache_write": 1.25,
    "cache_write_1h": 2
  }
}
```

「配置 → 用量与缓存」中的稳定布局、临时动态上下文和稳定素材采样均默认关闭。启用后会重排分组并覆盖世界书注入位置，可能影响模型行为及增加常驻输入。固定协议、可信剧情分支指令、宿主人格与核心事实保留在系统层，状态和普通检索材料作为数据分段处理；预算不足时先移除易重建的状态与低优先级数据，检索材料优先保留前部条目，再裁过长正文；保留用户正文和核心事实并提示超限。此预算计入系统层、当前输入与文本历史，媒体及供应商消息封装不作为 token 估算，不等于模型 token 窗口。固定状态栏提醒位于系统层，旧布局仍在用户正文末尾。素材采样窗口使用角色内独立计数，不随激活中断归零。

临时通道以已审阅的 AstrBot 装配与历史保存契约为边界，当前参考实现为 4.29.3 的 local 运行器及 OpenAI/Anthropic 适配器；版本号仅用于诊断。主路径及配置的回退路径都需通过检查，未知时使用系统尾部布局，不自动重发。宿主升级或定制实现可能使优化保守停用，原因可在日志、`/quill debug`、会话组面板与注入诊断查看。临时内容除源码契约核对外，还经过实际请求装配、重建、供应商序列化与历史过滤的本地能力自检；这些检查不替代成功模型、流式和工具多步的验收。已运行的隔离验收覆盖接口、面板和请求失败路径，成功模型回复、流式/工具多步与临时数据不落历史仍待真实模型验收。历史旧提醒清理暂缓。模拟检索仍是候选与预算画像，最终装配请查看真实轮次诊断。

用量页提供输入/输出并排柱图、调用与选定费用来源趋势，以及会话组、模型、用途、供应商/端点、角色排行；趋势与来源在同卡内左右排布，KPI 合并为一条统计带，筛选常显。排行可点击筛选，默认显示前七项和其他；缓存命中率与报告覆盖分开展示，明细可展开查看完整计数证据与价格说明。输入已含缓存，不重复叠加；未知量与已报告零分别展示。图表使用全部匹配记录，翻页仅影响明细；查询失败保留上次成功快照并明确提示。趋势仍按 UTC 日级分组，只显示查询中有记录的跨度，受保留期限与条数上限影响，不代表完整账单。小时分桶、本地自然日重分桶、点击日期筛完整明细与长期热力图留待后续查询能力扩展。设置与趋势数据在弹窗中查看；调用明细单行省略、展开为双列；窄窗口下所有页面统一收为图标侧栏。

旧写作库中已确认的历史孤儿索引会先在恢复副本上清理并做完整性检查，再清理原库中的残留；素材、命中计数与日志保留。原始备份仍保留，未知索引故障及真实完整性错误继续拒绝迁移。

## 上下文压缩与费用换算

「模型用量 → 设置」可开启自动压缩、填写文本估算 Token 上限，并从 AstrBot 供应商配置中选择压缩模型（留空使用主模型）。默认关闭；接近上限85%时压缩旧的纯文本轮，保留系统设定、当前输入和最近两轮。文本估算不等于供应商精确 token 或媒体/工具硬窗口，保留部分仍可能超过预警线。工具/媒体旧历史暂不拆分，压缩失败或未缩短时保留原文。此设置为插件全局配置，宿主自己的压缩策略保持独立。

`/quill compact` 可手动生成摘要，下次匹配请求使用；群聊与共享会话组需要管理员权限。压缩会有额外模型调用，单独计入「上下文压缩」用途。原文先写入插件数据目录的 `context_checkpoints`；最多500份、合计50MB，达到保护上限后停止新压缩。**检查点目录须单独备份，目前不包含在剧情备份zip中；恢复/维护面板尚未提供。** 会话组原始近期流保留，摘要只进入临时视图。

设置弹窗每次打开读取最新配置，只保存本次实际修改的项目；同一项目已在其他页面更新时，会提示关闭重开后核对。未修改的设置不会被旧表单回写，读取完成前保存按钮保持禁用。

手动整理只读取所选角色已绑定的对话；新角色没有历史时直接提示不足。共享组在来源前缀一致时支持连续多次整理与重载后复用摘要。近期历史不足时不压缩；检查点容量不足会在调用模型前停止，并提示先备份整理。

费用可选原币种、统一 CNY 或 USD，填写手动汇率「1 USD = N CNY」后换算展示；0表示未设置，不自动获取或猜测汇率。原始金额、币种和供应商报告/价格推算来源均保留，缺汇率与其他币种会明确未换算。换算视图便于比较，不等于供应商实际结算金额。

用量选择器按逻辑会话列出可读名称和短标识，跨入口共享组可以整体查看；「物理入口」可进一步筛选某个私聊/群入口。历史费用以发生时的会话归属保存，不因后来加入/退出会话组重写。

## 角色状态、总结与后台任务

无角色卡的旧状态也只迁移和备份一次，之后仍可由实际选中的首张卡接管。每个会话中的角色分别保存状态变量、注入轮次、开场标记和总结计数。升级前的旧状态只由首次接管它的角色继承，切到第二张卡从空状态开始，切回原卡可继续；流式与状态栏开关仍是会话级偏好。每轮开始时固定角色归属，在途切卡不会把旧轮的状态或后台总结写入新卡。未加入会话组时保持原会话隔离。

管理员可在「动态记忆 → 记忆浏览」选会话后点击「增量总结」，也可通过 `/memory learn` 发起。只有日志、还没有记忆的会话同样可选。总结从持久保存的进度继续，清除记忆或重启不会倒退进度；未配置模型或总结失败时不消费日志。成功但无需新增记忆的结果也会记录进度。每次只处理有界批次，积压较多时可再次发起。

「后台任务」页查看任务状态、进度和存储可用性。后台任务与会话组页面支持明暗主题、键盘操作和小窗口布局。记忆导入也在后台执行，同目标的进行中任务会复用。取消在安全点生效，已提交的步骤保留；取消中再次提交同一任务会明确要求等待，取消后发生的实际错误仍如实显示；完成记录最多保留 10 分钟、100 条，重启不恢复任务本身。导入取消后可重试同一份文件，已成功导入的同源记录不会重复写入。

`/memory clear` 清当前角色的记忆与日志；`/quill reset` 保留长期记忆，清当前角色的日志与对应原生对话。中断的清理会保留操作登记，重载或下次进入该会话时续做；恢复失败会保留原阶段、退避重试并暂停相关会话的生成，可用 `/quill debug` 或后台任务页查看；应先排除故障，不能绕过未完成的清理继续剧情。启用的总结、反思尚未消费的超期日志会保留并显示积压；停用的消费者不阻塞清理。

升级会在数据目录的 `.schema_backups` 中保留经过恢复校验的旧库和旧状态副本，副本不包含在普通剧情 ZIP 中。它们含历史数据，请像原数据一样保存；遇到未来版本会拒绝相关读写，可在任务页查看原因；记忆库和文档库分别初始化，一方故障不连带关闭另一方。恢复校验会关闭 SQLite 句柄，避免 Windows 文件占用。Windows 文件权限继承目录 ACL，不能把 POSIX 权限位当作 Windows ACL 加固。这里提供的是存储保护和分阶段恢复，完整存读档与撤销仍属后续规划。

M3 已在隔离 AstrBot 4.29.3 上验证接口、WebChat、SQLite 回滚/重载恢复、未来版本保护及真实浏览器任务交互。成功模型总结、空产出/重复产出和模型返回期间跨卡并发仍待真实模型环境验收。

## 会话组（开发中）

当前代码包含后台任务管理和正在开发的会话组，**会话组尚未完成全部验收**。请先在独立数据根备份、测试。Windows 实机迁移、真实聊天平台编辑与重投递、成功模型跨入口续写、流式/工具多步历史隔离和真实缓存账单仍需本地验证。

管理员进入「会话组」，点「新建会话组」在弹窗中选择已观测入口和共享角色，预览范围后保存；保存后弹窗关闭回到列表，可继续创建下一个组，点组名可编辑已有组。入口尚未出现在列表中时，先从该私聊或群聊发送 `/quill`，再点「刷新入口」或切回本页。默认从建组时开始共享；也可明确选择复制一个入口的同角色变量、纳入所选入口同角色的旧记忆和日志。原数据保留，其他角色不自动合并。

同组共享角色选择、角色状态和近期纯文本剧情，回复仍回到发起本轮的物理入口。模型与渲染偏好保留各入口配置；图片、音频和工具内部消息暂不跨入口复制。组内请求排队，不同组可并发；正在生成时拒绝修改成员、切换共享角色或解散，需等本轮结束后重试。由管理员在会话组面板移除入口后，恢复该入口原有独立数据，组历史保留为管理员档案，已经分享的信息无法收回。

共享近期视图的目标范围是 **AstrBot 已审阅内置运行器的 OpenAI / Anthropic 路径**，当前参考宿主为 4.29.3。M2 修复已更新共用能力判断；M7 整体仍是未完整验收的开发快照。只支持一个 AstrBot 实例内的多入口，尚未验收成功模型回复、流式回写和真实平台账号之间的剧情续接。

群聊以及已入组私聊的共享写操作都要求管理员白名单，可填写用户 ID，或用 `平台实例ID:用户ID` 限定平台；Web 面板使用 AstrBot 的管理员鉴权。参与者显式关联只影响后续身份标识，不授予权限或重写历史。组级 `/quill reset` 与 `/memory clear` 会先列出所有受影响入口，再提供含当前组标识和修订号的确认命令。面板删除共享记忆同样先核对影响入口和修订号，范围变化须重新确认。数字续接读取共享历史的实际菜单，支持 2–9 个连续编号或项目符号选项及旧式菜单标记；跳号菜单不擅自重编号。消息修订只保留新版进入近期剧情，旧版及对应回复保留审计。

本分支会把记忆数据库迁移到新的存储版本，迁移前生成并校验安全副本。回退插件源码不等于回退数据；旧版可能拒绝写入新库。完整存读档与撤销仍属于后续里程碑。

| RAG | Embedding/Rerank 提供商、本地模型、分块参数、检索数量、记忆开关 |
| 性能 | Prompt 截断上限、最低回复字数 |
| 状态栏 | 开关、字段定义、格式模板、剧情走向选项 |
| 调试 | 调试日志开关、全量备份导出/恢复 |
| 权限 | 管理员 ID 白名单（仅群聊写指令需要） |

> **权限说明**：`admin_users` 仅作用于聊天平台的群聊写指令。配置后仅白名单用户可在群聊执行写操作，留空时群聊写指令被拦截。私聊与 Web 面板编辑不受此限制——Web 面板由 AstrBot 鉴权保护。
>
> 写指令的范围是「会改动持久状态」的全部子命令：角色卡切换/取消/导入、世界书与文档的绑定/解绑/重载、记忆的删除/清空/写入、`/quill reset`、`/reinject`、`/stream` 与 `/quill statusbar` 的写入、以及 `/quill debug`（输出含会话标识与注入构成）。读类指令（list / info / search / 无参数状态查询）在群聊对所有人开放。

## 开发约定

**日志一律使用 `from astrbot.api import logger`**，禁止 `import logging` /
`logging.getLogger()`。这是 AstrBot 插件市场的硬性上架规则（LLM Guard 审查项），
违反会直接 Rejected。全仓库应当满足：

```bash
grep -rn "import logging" --include=*.py .   # 期望输出为空
```

带 `__main__` 自测入口的模块（`kb.py`、`state.py`、`activation.py` 等）
若要在插件外直接 `python <file>` 运行，用 `_astrbot_bootstrap.ensure_astrbot_importable()`
把 AstrBot 加入导入路径即可——不要为了跑自测而回退到内置 logging。

**测试只做端到端**：本项目不维护单元测试 / 回归测试，验收一律在真实 AstrBot 实例上完成
——真实聊天链路注入指令与对话、真实面板操作（CDP），用例自带断言并在跑完清理测试数据；
用例脚本放在本地 `.build/harness/`（不入库）。

### LLM Hooks 执行流程

```
on_waiting_llm_request (priority=100)  →  控制流式模式
        ↓
on_llm_request (priority=100)  →  检测激活 + 注入 System Prompt + 改写 tool desc + 追加 tail
        ↓
on_using_llm_tool (priority=200)  →  Markdown 清理 + 状态栏解析/格式化/剥离
        ↓
on_llm_response (priority=10)  →  状态栏兜底/剥离
        ↓
on_llm_tool_respond (priority=10)  →  停止 agent loop + 记忆存储
```

## FAQ

**Q: 为什么不直接使用市场上的世界书插件？**
A: 大多数世界书插件仅提供关键词注入。QuillPlus 在此基础上补充了角色卡管理、写作素材库、文档 RAG 和动态记忆四个附加模块，构成完整的 RP 工作流。

**Q: 可以在手机端使用吗？**
A: 可以。通过发送指令（`/char`、`/wb`、`/memory`、`/quill` 等）在聊天窗口直接管理功能，无需打开 Web 面板。

**Q: 角色卡和其他插件冲突吗？**
A: QuillPlus 使用独立的 JSON 存储，不依赖 AstrBot 原生的 persona 系统，不会影响其他插件数据。v5.3.2 起还支持把 AstrBot「人格」页里的人格**只读导入**为角色卡：只读取人格正文交给摘要模型转换，不修改、不删除 AstrBot 里的人格，导入结果也只是本插件自己的角色卡。

**Q: Embedding 和 Rerank 模型推荐？**
A: 推荐 SiliconFlow 的 `Qwen3-Embedding-8B` 和 `bge-reranker-v2-m3`。不配置时自动使用本地模型 `BAAI/bge-small-zh-v1.5`。

**Q: 动态记忆会串群吗？**
A: 使用 `event.unified_msg_origin` 作为 session_id，SQL 按 session_id 过滤，天然隔离。

**Q: 状态栏不显示或显示不正确？**
A: 检查配置中状态栏是否开启；确认 LLM 输出格式是否匹配；可尝试开启前置模式提升服从度。

**Q: 群聊指令不能用了？**
A: 检查 `admin_users` 是否已配置。留空时群聊写指令被拦截，配置后仅白名单用户可执行。

**Q: 切换 Embedding 模型后 RAG 检索失效？**
A: 切换提供商会导致向量维度变化，插件会自动检测并重建 FAISS 索引，旧文档需重新上传。

### 前端面板加载说明

AstrBot 框架的 Plugin Pages 静态文件服务默认设置 `Cache-Control: no-store`（强制禁用缓存）。面板由 index.html 与独立 CSS/JS 模块组成（约 30 个文件，合计约 350KB），每次刷新都会按文件重新加载。如果加载较慢，可以通过以下方式优化：

1. **反向代理缓存**：在 AstrBot 前方部署 Nginx/Caddy，对插件 Pages 路径添加缓存头
2. **本地缓存**：浏览器开发者工具中禁用 "Disable cache" 选项（仅对非 DevTools 窗口生效）

> 该限制来自 AstrBot 框架层面。面板本身不依赖任何外部 CDN——界面字体异步加载，失败时自动回退系统字体；自绘下拉、右键菜单、方向键导航均为零依赖手写实现。
