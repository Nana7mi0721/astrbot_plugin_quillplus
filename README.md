## 💡 简介与核心特性

**QuillPlus (羽笔)** 是专为 [AstrBot](https://github.com/Soulter/AstrBot) 设计的深度角色扮演（Role-Playing）增强核心引擎。

与单纯提供关键词匹配的世界书插件不同，QuillPlus 提供了一套**闭环式角色扮演工作流**：从角色的核心人设规范、宏观世界观设定、专业虚构写作修辞指导，到外部知识检索、长期情景记忆沉淀、细粒度状态量化追踪以及调用计费监控。

### 核心亮点一览

1. **六合一全要素沉浸系统**：世界书、写作素材库、角色卡、文档 RAG、动态记忆、状态栏六大子系统协同运作，按需动态装配。
2. **多源角色卡生态兼容**：全面支持 SillyTavern Character Card V2 与 CCv3 标准（PNG/APNG/CHARX/JSON/文本），内嵌世界书自动解包，独创短 ID 解耦技术（改名零断链），支持从 AstrBot 原生「人格」只读转换导入。
3. **分层提示词装配与优先级截断**：4 层 Prompt 精细排布（协议层 → 素材层 → 触发层 → 安全层），超出模型预算时按优先级从低到高优雅截断，核心设定永不丢失。
4. **平行宇宙双轴隔离**：会话维度（群/私聊）与角色维度双轴隔离（`target_id::persona_id`），同一群聊随意切换角色绝不串戏，重置剧情亦可保留长期记忆。
5. **六级降级状态栏与决策模式**：L1–L6 渐进降级解析（Code Block → LOVE_DATA → STATUS → 动态正则 → Lenient → LLM），支持决策模型（JEV / OpenAI Decisions 协议）结构化走向判定，自动适配 QQ/微信等纯文本平台与 Telegram/Slack/KOOK 等富文本平台。
6. **真实模型用量与多币种记账**：秉承「宁缺勿猜」原则，精准记录输入、输出、缓存读写 Token，支持配置阶梯单价与汇率换算，独立台账不随剧情存档回退。
7. **跨平台跨入口会话组**：支持同一 AstrBot 实例下的多入口（群/私聊/WebChat）共享剧情与记忆，自动标注来源入口与说话人，根治场景跨入口认领串台问题。
8. **安全第一与原子存储**：所有配置与运行时状态采用 `tmp + flush + fsync + os.replace` 原子写入；写类指令全部受管理员白名单保护；敏感数据出口均设防。
9. **原生桌面级交互面板**：基于 Apple HIG 规范全面重塑的 macOS 27（Liquid Glass）桌面形态 WebUI，10 个独立功能页面，纯原生 ES Modules，零外部 CDN 依赖。

## 🚀 快速开始

### 1. 环境依赖

确保运行环境满足以下要求：
- **Python**: `>= 3.10`
- **AstrBot**: `>= 4.26.0`（已在 AstrBot 4.29.x 系列深度验证）

安装核心可选依赖（用于图像角色卡解析与本地向量计算）：

```bash
# 图像处理（用于 PNG 角色卡头像裁剪与嵌入数据读写，未安装则仅支持 JSON/文本卡片）
pip install "Pillow>=10.0.0"

# 向量计算与本地索引（用于本地文档知识库与动态记忆混合检索）
pip install "faiss-cpu>=1.8.0" "numpy>=1.24.0" "aiosqlite>=0.19.0"
```

> 💡 *Web 框架依赖（FastAPI / Quart）由 AstrBot 自身提供，无需重复安装。*

### 2. 插件安装

1. 将本插件目录克隆或放入 AstrBot 的 `data/plugins/` 目录下（目录名通常为 `astrbot_plugin_quillplus`）。
2. 启动或重启 AstrBot。
3. 打开 AstrBot WebUI → **插件管理** → 找到 **羽笔 (astrbot_plugin_quillplus)** → 点击 **启用 / 重载**。

### 3. 三步开箱即用

1. **设置管理权限**：  
   进入 AstrBot WebUI → **插件配置** → **羽笔** → 在 **权限 (permissions)** 分组中配置 `admin_users`（填入你的平台用户 ID，如 QQ 号；仅用于保护群聊中的写操作，私聊默认放行）。
2. **配置语言模型**：  
   在 **RAG 与动态记忆 (rag)** 分组中选择你的 `llm_provider_id`（用于记忆提纯、反思与文档检索，建议选择轻量高速模型降低成本）。
3. **验证与体验**：  
   - 在聊天窗口中发送 `/quill` 查看系统健康度与运行概览。
   - 发送 `/char` 查看并切换预置角色卡。
   - 也可以直接点击 AstrBot WebUI 左侧 **Pages** 打开羽笔管理面板进行可视化配置。

### 1. 角色卡系统 (Character Cards)

实现完整的 Character Card V2 与 CCv3 标准规范，支持自由导入导出与深度人设注入。

- **多源格式无损导入**：支持 PNG / APNG / JPG / WebP / JSON / CHARX（ZIP 容器）文件上传，或纯文本/W++ 格式剪贴板粘贴导入；CHARX 会校验解压体积与压缩比、拒绝路径穿越与符号链接条目，远程资源一律不下载；卡片内嵌的 `character_book` 会自动提取并自动绑定为专属世界书。
- **导入前先看清格式**：导入时自动识别 Tavern V1、V2/V3、嵌套 JSON、Pygmalion、Agnai/BYAF、oobabooga YAML、SBF/Boostyle、W++ 或纯文本，并给出识别置信度；声明了规格却对不上的卡片直接被拒绝并说明原因。导入后可查看报告：哪些字段已映射、哪些原始字段被原样保留、哪些特性（如 V3 昵称、群聊开场白、资源清单）暂不生效，低置信导入会提示核对内容。
- **按需导出 CCv2 / CCv3**：导出前可预览将生成的文件名、体积与冲突提示，按整本或逐条挑选要随卡带走的世界书条目；系统提示、后置指令与备选开场白会还原成标准字段，有头像时可导出 PNG 角色卡。
- **身份键与显示名彻底解耦**：新建或导入卡片均自动分配 12 位十六进制短 ID 作为内部永恒唯一标识。**改名只是改名**——对话历史、绑定世界书、聊天记忆永不丢失断联。
- **由 AstrBot 人格只读导入**：面板一键读取 AstrBot 原生「人格」列表，调用配置的摘要模型自动提炼人设、性格、背景与开场白，直接生成角色卡（原生人格只读，绝不修改或删除 AstrBot 数据）。
- **内置头像裁剪编辑器**：面板内置可视化头像裁剪工具，支持拖拽平移与滚轮无级缩放，导出 300×300 规范方图。
- **开场白与首轮激活机制**：首次切换角色时自动注入开场白（`first_message`）；开场白支持多条候选题材切换；切卡时自动切断 AstrBot 原生提示词，避免不同人格串扰。

### 2. 世界书系统 (Worldbook)

强大的情景背景与世界观知识注入机制，精准控制设定的出场时机。

- **常驻条目与动态触发**：常驻条目随每次请求无条件注入构筑世界观底层逻辑；动态条目通过关键词模糊匹配，支持调整灵敏度（`match_sensitivity`）。
- **条件解锁条目 (Condition Unlocking)**：设定条目可附加判定条件（如 `好感度 >= 70`、`剧情阶段 in 约会,婚礼`、`堕落值 > 30`）。只有当当前会话变量满足条件时条目才会被激活注入，条件不满足或变量缺失时自动静默忽略（可在注入诊断明细中查验近失原因）。
- **进阶规则编排**：条目可设置延迟启用、粘性、冷却、互斥组、扫描窗口、主次关键词 AND/OR 与受限递归；支持 `@@depth <N>` / `@@role` 装饰器把正文按消息深度插入历史；面板可直接编辑，注入诊断会说明命中或未命中的原因及剩余轮数。
- **角色专属世界书集合**：角色卡可绑定一组专属世界书；切换角色时对应世界书自动挂载，卸载其他角色设定。
- **注入位置智能适配**：支持前置模式（`user_prefix`，在用户提问前注入）与系统尾部模式（`system_end`），前置模式对各类现代模型拥有极高的上下文遵循度。

### 3. 写作素材库 (Writing Materials)

针对小说级角色扮演沉浸体验打造的虚构写作知识库（Writing Resources）。

- **出厂 65 条专业写作修辞指引**：涵盖叙事视点、感官细节描写、节奏快慢张弛、对白潜台词、场景渲染、情绪起伏等多个维度。
- **毫秒级 SQLite + FTS5 全文检索**：支持多关键词、次级关键词加权匹配；根据对话上下文自动检索最契合的写作指导原则注入模型。
- **素材体检与安全停用**：面板内置「素材体检」工具，自动扫描过宽关键词与流程控制风险；针对旧版本遗留的控制指令类素材，提供一键「备份并停用所选」功能，保留正文与命中统计，安全无忧。
- **分类绑定隔离**：角色卡可独立勾选允许使用的写作素材分类，避免将特定题材风格串入通用扮演。
- **写作风格预设**：按叙述视角、对白密度、用词、节奏、感官等互斥维度各固定注入一条素材，避免相反文风指令同时出现；角色卡可单独覆盖或关闭全局预设。

### 4. 文档知识库 (Doc RAG & 内置库兼容)

外部大文本/设定集的检索增强生成（RAG）体系。

- **多格式切片与向量检索**：支持 `.txt`、`.md` 纯文本，段落优先分块配合 Overlap 保持语义连贯；FAISS 向量索引与 SQLite 事务一致性保护。
- **双向兼容 AstrBot 内置知识库**：完全打通 AstrBot 原生「知识库」页配置的库（以 `kb:库名` 标识）。无需重复导入文档或重复配置 Embedding，内置库与本地文档同权检索并支持混合注入。
- **子知识库分组 (Metadata Grouping)**：本地文档支持建立子分组（`grp:组名`），所有本地文档共用单份向量索引，改组改名无需重新上传计算向量。
- **细粒度单篇挂载**：角色卡支持三级绑定（大组全选 → 分组 → 单篇文档）。支持仅绑定内置库或本地库中的特定单篇文档（如 `kb:世界观/魔法设定.md`），检索池智能放大筛选，绝不被同库无关文件挤占。
- **一键向量重建**：切换 Embedding 模型或维度漂移时，面板支持利用本地持久化的文档文本一键重新生成向量索引，无需重新上传。

### 5. 动态向量记忆 (Dynamic Memory)

模拟人类记忆机制的长期上下文沉淀与联想检索系统。

- **平行宇宙双轴隔离**：采用 `mem_session_id = "{target_id}::{persona_id}"` 作为记忆主键，不同群聊隔离、同一群聊不同角色隔离，彻底杜绝切卡记忆污染。
- **核心记忆锚定 (Core Memories)**：关键事实或深层人设可通过面板或指令钉住为核心记忆（`is_core=1`），享受三重免疫（不参与 Top-K 竞争、不受时间衰减衰减、不被遗忘算法修剪），始终以 `<core_memory>` 标签优先注入。
- **自然语言直接记诵**：在日常对话中直接发送 `@记住：我们已经在去年夏天订婚了`，系统自动写入核心记忆，无需打开后台。
- **混合检索与艾宾浩斯时间衰减**：FTS5 词面匹配 (BM25) 与向量语义相似度混合检索，经 RRF 融合排序，并叠合艾宾浩斯遗忘曲线对较久远记忆实施合理降权。
- **闲时自主反思守护进程**：后台服务在系统空闲时自动分析未提纯的连续对话历史，提炼出关键情节与关系变化，增量写入记忆库。

### 6. 状态栏与剧情决策 (Status Bar & Decision)

将角色的好感度、心情、体征与剧情走向选项实时量化与结构化展现。

- **六级渐进式降级解析 (L1–L6 Registry)**：
  1. `L1 Code Block`：标准 Markdown 代码块解析。
  2. `L2 LOVE_DATA`：单行管道分隔格式（实际命中率最高的一级）。
  3. `L3 STATUS`：多行键值标签格式。
  4. `L4 动态正则`：根据配置字段白名单动态构造正则抽取。
  5. `L5 Lenient`：宽松容错提取与会话历史值平滑融合。
  6. `L6 LLM 智能提取`：前 5 级均失败时调用轻量模型智能结构化提取（带 3 秒熔断超时保护）。
- **多平台方言自适应**：按平台实际支持的文本语法选模板——QQ、微信等用纯文本分隔线，Telegram、Slack、KOOK 用各自的粗体与围栏规则，正文中的反引号、反斜杠会先转义，避免字段值提前关闭模板围栏；未收录的平台先按纯文本保守显示，可在配置的 `status_bar.dialect_overrides` 中手动指定某个平台的方言。
- **决策模式 (Decision Mode)**：支持接入各类兼容 System One 与 OpenAI Decisions 协议的决策模型端点（如 TypeSafe JEV、OpenRouter Decisions 等），由独立小模型对剧情分支进行置信度仲裁，本地数字选择（1/2/3）零 Token 瞬间响应。
- **历史状态栏智能剥离**：关闭状态栏时，或在发送给模型的历史上下文中，自动剥离以往生成的冗余状态栏标记，避免历史累积导致上下文膨胀或模型误模仿。

### 7. 模型用量与费用统计 (Usage & Cost)

透明、真实、精细的模型消耗与计费中心。

- **事实记账原则**：输入、输出、缓存读取、缓存写入互斥分列，供应商未提供字段明确标记「未知」，绝不将未报告猜测为零。

### 8. 后台任务管理 (Background Tasks)

异步长耗时任务的调度与可观测中心。

- **统一任务注册表 (TaskRegistry)**：涵盖大批量记忆导入、手动增量总结、文档向量全量重建等长操作。
- **幂等与防并发碰撞**：相同目标的重复任务自动合并，避免资源浪费与写入冲突。
- **安全检查点取消**：取消操作在当前安全处理步骤完成后优雅退出，绝不产生半截损坏数据。

### 9. 跨平台会话组 (Session Groups)

打破单群/私聊壁垒的多入口协同剧情共享系统。

- **多入口剧情互联**：允许将同一个机器人的多个物理入口（例如特定的 QQ 群、私聊、Discord 频道或 WebChat）编入同一个会话组，共享角色身份、剧情变量与情景记忆。
- **来源与说话人精确标注**：共享上下文中每条消息均标注其来源入口与说话人（`〔来自：入口｜说话人：名（本入口/别处）〕`），明确告知模型别处入口的场景道具属于彼处，从原理上消除跨入口认领串台问题。
- **独立发信与权限隔离**：回复内容始终精准送回发起对话的物理入口；共享组的重置与敏感操作严格要求管理员二次确认。

### 10. 上下文压缩与提示词缓存 (Compact & Cache)

长对话稳定性保障与 API 成本优化。

- **手动压缩指令**：支持管理员随时发送 `/quill compact` 手动触发整理。
- **稳定提示词缓存布局 (试用)**：重排提示词分组结构，将不变的系统协议与常驻人设置于前列，大幅提升主流大模型供应商（OpenAI、Anthropic、DeepSeek 等）的上下文缓存命中率，降低调用成本。

## 🔍 注入诊断与体检 (Trace & Diagnostics)

排查「为什么这个设定没注入？」、「AI 为什么失忆了？」的专业诊断黑盒。

- **一键静态体检 (Static Lint)**：自动扫描世界书与角色卡中是否存在重复词、宽泛死词、语法错误条件、幽灵绑定等潜在隐患。

## 🛡️ 权限与数据安全

QuillPlus 在多用户、跨群聊部署环境中拥有严密的安全防护体系：

1. **写指令权限收口**：
   - 聊天平台全部具有破坏性或状态改动能力的指令（切卡、绑定、解绑、重载、增删记忆、重开、配置开关）统一经过权限门校验。
   - 私聊环境放行，群聊环境仅允许 `admin_users` 白名单用户操作；留空时群聊写操作严密拦截并提示自身 ID。
2. **Web API 分级鉴权防外带**：
   - Web 面板直接集成 AstrBot 管理员凭证校验。
   - 数据全量导出类端点（全量备份 Zip、跨会话记忆导出、聊天日志导出、角色卡导出）强制实施管理员校验，杜绝第三方插件凭证外带全群数据。
3. **敏感凭据脱敏防泄露**：
   - 决策模型等 API Key 在前端读取接口中统一以哨兵掩码（`"__saved__"`）下发，杜绝明文密钥暴露与二次保存覆盖。
4. **底层存储防损坏防崩溃**：
   - 状态 JSON 写入全流程采用 `*.tmp` 临时文件写入 → `flush` → `fsync` 刷盘 → `os.replace` 原子替换，防御断电或崩溃损坏。
   - SQLite 升级自动生成快照并预校验完整性（`PRAGMA integrity_check`），且显式闭合句柄适配 Windows 文件锁定机制。

## ❓ 常见问题排查 (FAQ)

<details>
<summary><b>Q1: 为什么在群聊里使用 <code>/char</code>、<code>/wb</code> 提示无权操作？</b></summary>

> **A**: 这是系统的权限安全保护机制。为了防止群友随意切换角色或篡改设定，所有会改动持久状态的指令在群聊中受 `permissions.admin_users` 白名单保护。请在 AstrBot WebUI 的插件配置中填入你的平台账号 ID；在私聊中无需配置即可自由操作。
</details>

<details>
<summary><b>Q2: 切换角色卡后，之前的聊天记忆会混在一起吗？</b></summary>

> **A**: 绝对不会。QuillPlus 采用严格的「平行宇宙双轴隔离」机制，记忆库的主键由「会话 ID + 角色卡短 ID」联合构成。为不同角色保留完全独立的记忆库与对话流，切回原角色即可无缝继续旧剧情。
</details>

<details>
<summary><b>Q3: 状态栏在 QQ / 微信等平台上显示乱码或多余星号怎么办？</b></summary>

> **A**: 插件内置了「平台方言自适应机制」：QQ、微信等纯文本平台自动使用分隔线模板，Telegram、Slack、KOOK 使用各自支持的粗体与围栏语法。如果你的平台未自动识别，可在配置的 `status_bar.dialect_overrides` 中按 `平台=方言` 手动指定（方言可选 plain、markdown、telegram、slack、kmarkdown）；旧的 `status_bar.plain_platforms` 仍可把平台强制设为纯文本。
</details>

<details>
<summary><b>Q4: 切换了 Embedding 模型后，之前上传的知识库文档还能检索吗？</b></summary>

> **A**: 不同的 Embedding 模型向量维度与语义空间不同。切换模型后，进入 Web 面板的「文档知识库」页面，点击「重建向量」按钮，系统会直接利用本地持久化保留的文档原文自动重新向量化，无需重新找文件上传。
</details>

<details>
<summary><b>Q5: 为什么流式模式下状态栏有时无法被清洗或正常解析？</b></summary>

> **A**: 现代 LLM 的流式输出是一字一句吐出，正则表达式无法对半截文本进行稳定匹配。QuillPlus 默认的流式模式为 `auto`：在触发了 RP 扮演的激活轮次会自动提前关闭流式，以确保状态栏能够完整捕获并渲染；普通闲聊仍保持流式。如需强行调试，可发送 `/stream off`。
</details>
